# 来源与证据管理

## 来源清单

开始写作前建立 source manifest：URL/路径、标题、作者、日期、权限级别、访问状态、正文覆盖、权威性、将支持的章节。

访问状态只允许：full（完整正文）、partial（摘要/片段/有限页数）、metadata-only（仅元数据）、blocked（无权限或网络失败）。

## 证据标签

- **来源事实**：文档、代码、论文或官方页面直接支持；
- **推导**：由来源事实经过明确数学或逻辑步骤得到；
- **教学构造**：为解释而创建的数值、案例或类比；
- **建议**：基于经验的实践建议；
- **未核实**：线索存在但未获得权威正文。

正文不必反复显示标签，但作者必须维护 ledger，并在高风险或易混淆处显式说明。

## 多来源冲突

按以下顺序处理：当前线上规范/官方 API > 当前设计文档 > 历史设计文档 > 培训材料 > AI 速览 > 搜索摘要。若新旧版本无法判断，不要自行合并，列出冲突和日期。

## 认证文档

优先顺序：lark-cli 用户身份只读 API → 已授权浏览器/CDP → 用户导出文件或文本 → 搜索摘要线索。

不要打印、保存到项目或转述 Cookie/token。浏览器虚拟滚动页面要逐视口滚动并累积块内容，不能只在底部读取一次。正文提取后记录覆盖限制。

## 来源覆盖表

交付前生成“章节 / 核心主张 / 来源 / 定位 / 状态”表。所有关键公式、实验数字、内部模块职责必须有来源；无法定位的内容降级为教学解释或删除。
