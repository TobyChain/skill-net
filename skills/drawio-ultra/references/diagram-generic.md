# 通用图表布局指南

流程图、业务架构图、ER 图、状态机图、思维导图的布局建议与决策逻辑。时序图见 `diagram-sequence.md`，模型架构见 `diagram-ml-architecture.md`。配色与节点模板按所选风格读取 `style-product.md` 或 `style-academic.md`。

## 图表类型选择

按内容结构选择，不要机械套模板；用户指定类型时优先执行，仅明显选错时简短提醒：

- 流程步骤、决策分支、算法逻辑：流程图
- 模块关系、服务依赖、部署层次：架构图
- 服务调用、消息交互、时序过程：时序图
- 实体、字段、主外键关系：ER 图
- 生命周期、状态迁移、事件驱动：状态机图
- 概念梳理、知识组织、层级扩展：思维导图

## 布局建议

### 流程图

- 主干流程保持单向阅读
- 分支判断使用菱形节点
- 决策出口只保留短标签（是/否）
- 避免大量连线交叉

### 架构图

- 先画层（容器），再画层内节点
- 相同职责的节点放进同一容器（swimlane 或虚线分组）
- 数据流和控制流不要混成一类箭头
- 外部依赖和内部模块视觉上拉开层次

### 时序图

读取 `diagram-sequence.md`（参与者头部、生命线、激活条、消息箭头的精确坐标规则）。

### ER 图

- 实体名清晰、字段简短
- 主键、外键关系明确
- 不要把所有字段塞进一张巨大的 ER 图；复杂系统优先拆分子域

### 状态机图

- 状态是节点，事件是边
- 状态名和边标签都不要写成长句
- 开始和结束状态要明显（实心圆 / 环形圆）

### 思维导图

- 从中心主题向外发散
- 第一层分支控制在 4-8 个
- 同层级节点保持视觉一致

## 常用节点形状路由（产品风）

| 语义 | shape |
| --- | --- |
| 普通节点 / 服务 | `rounded=1` 矩形 |
| 条件判断 | `rhombus`（菱形） |
| 数据库 | `shape=cylinder3`（圆柱） |
| 分组 / 集群 | `swimlane` + 虚线描边 |
| 主标题 | `text` 节点，fontSize=20 |

具体 fillColor/fontColor 按 `style-product.md` 语义配色表替换。

## 生成顺序

标题 → 容器/分组 → 核心节点 → 连线 → 标签与旁注。不要边写边想结构。
