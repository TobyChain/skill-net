## 1. 教材与报告的区别

报告回答“来源讲了什么”；教材回答“读者学完能做什么”。每一条内容都要服务于能力变化：辨认、解释、计算、诊断、设计或评估。

先写学习承诺：目标读者、先修知识、学习后能力、建议时间。删除不能服务这些目标的细节，或移到“延伸阅读”。

## 2. 知识依赖图

建立概念表：

| 字段 | 内容 |
|---|---|
| 概念 | 唯一名称及别名 |
| 类型 | 定义 / 机制 / 公式 / 工程组件 / 决策 |
| 先修 | 理解它之前必须掌握什么 |
| 下游 | 它支撑哪些概念或任务 |
| 证据 | 来源与定位 |
| 难度 | 基础 / 核心 / 深入 |
| 易错点 | 常见误解或混淆对象 |

先做拓扑排序，再聚类为章节。出现循环时，选择一个概念作直觉预览，后文再正式定义。不要把来源目录直接当教材目录。

## 3. 章节契约

每章开头包含：

- **本章解决的问题**：一个真实问题或决策。
- **先修知识**：链接到前章或给 3 句以内回顾。
- **学习目标**：2–5 个可验证动词，如“计算”“区分”“诊断”“设计”，避免“了解”。
- **预计时间**：用于控制认知负荷。

每章正文至少包含：

1. 具体情境或动机；
2. 定义、模型或机制；
3. 逐步推导或系统流程；
4. 一个 worked example 或真实案例；
5. 一个边界条件、反例或常见误区；
6. 2–5 道练习；
7. 可折叠答案或评分标准；
8. 来源定位与置信度。

## 4. 讲解顺序

默认使用：问题 → 直觉 → 正式定义 → 机制/推导 → 例题 → 反例 → 练习 → 小结。

复杂公式使用：符号表 → 单位 → 假设 → 逐步变形 → 数值例题 → 极端情况 → 与相邻公式比较。

复杂系统使用：输入 → 阶段职责 → 数据变化 → 输出 → 失败模式 → 监控指标。

## 5. 例题设计

每个核心概念至少有一个例题。例题要模仿经典教材的功能，而不是文风：给定明确、求解明确、步骤完整、最后解释结果。

标准例题使用 article.worked-example，包含：编号和题名、已知、求、分步解答、业务解释、自检。例题数据必须可追溯或明确标为教学构造，不要伪装成线上真实数据。

对新手使用脚手架序列：

1. 完整例题：展示方法选择和决定性步骤；
2. 近迁移题：复用同一对象，只改变一个条件，可提供折叠提示；
3. 独立变式：不提示方法，让读者判断适用条件；
4. 章末综合题：连接多个已学概念，必要时加入边界、反例或实现验证。

后续论证若依赖某道练习的结果，要显式链接结果或答案，不能留下隐藏先修。

## 6. 练习与答案

每章练习覆盖四层中的至少两层，核心章覆盖全部四层：

1. **回忆**：定义、符号、模块职责；
2. **应用**：代入计算或走完流程；
3. **迁移**：条件变化后判断结果；
4. **综合**：诊断、设计实验、权衡方案。

每题标注目标、难度和答案。选择题解释错误选项；计算题展示关键步骤；开放题提供评分 rubric。提示与完整答案分离；提示指出下一步观察对象，但不要把题目降成机械代入。答案默认折叠，并使用 data-objective 和 data-level 关联目标与难度。

编程题必须给输入、输出、约束和测试入口；实验题必须给比较对象、预算、数据划分、指标和可证伪的假设。先独立解题或运行数值检查，再接受最终题面。

## 7. 多层读法

支持三条路径：

- **15 分钟主干**：学习承诺、路线图、每章小结、关键公式；
- **完整学习**：正文、例题、误区、练习；
- **工程深挖**：来源定位、实现组件、实验与监控。

使用 P0/P1/P2 或“基础/核心/深入”标记内容，不要把所有信息放在同一阅读优先级。

## 8. 篇幅分配与运行案例

按读者缺口和概念难度分配篇幅。对“新手学习一篇论文/设计文档”，可从以下比例起步：问题与必要基础 25%，继承方法 15%，核心方法与例题 30%，证据/比较/边界 15%，练习与解答 15%。这只是编辑起点，不是验收定律。

在关联章节间复用一个 running case。每次只改变一个有意义的条件，并说明什么保持不变、什么改变、为什么旧解释不再充分。避免背景铺垫过长而核心方法过薄，也避免逐段复述来源却保留所有隐含假设。

## 方法来源

本设计吸收了 textbook-anything 仓库 commit 2bb4c91 的教学流程：先确定读者与可观察目标，用 requirement table 反向规划，采用完整例题—近迁移—独立变式—综合题的练习序列，并对 substantial 教材执行两轮完整写作、构建与检查。这里保留的是可复用方法，不复制其示例题目或成品教材内容。
